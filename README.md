# Game Boy and Game Boy Color for Analogue Pocket, with cheats

Two Pocket cores, one for the Game Boy and one for the Game Boy Color, that can
apply cheat codes to a running game, on a ROM from the SD card or on a real
cartridge in the slot.

**Based on [budude2/openfpga-GBC](https://github.com/budude2/openfpga-GBC) by
budude2**, which is a Pocket port of
[Gameboy_MiSTer](https://github.com/MiSTer-devel/Gameboy_MiSTer), carrying Till
Harbaum's 2015 copyright and later contributors'. Everything that ships here is
theirs apart from the cheat engine.

What this fork adds is six modules in `src/gb/`, the hooks that reach them in
`src/core/core_top.sv` and `src/gb/gb.v`, and a data slot plus four menu
entries in `pkg/`. Nothing else in `src/gb/` is new; every other file there is
upstream's.

| | |
|---|---|
| `cheatcodes.sv` | the code store and the compare that applies a Game Genie patch. Carries Kitrinx's 2019 copyright, from MiSTer |
| `cheat_loader.sv` | parses a libretro `.cht` file into code entries |
| `cheat_poker.sv` | writes GameShark codes into RAM once a frame |
| `cheat_osd.sv` | draws the switches and the cheat names over the picture |
| `cheat_titles.sv` | holds the text of each name so the overlay can say which are on |
| `cheat_font.sv` | the glyphs, generated by `tools/cheats/genfont.py` |

See [docs/CHEATS.md](docs/CHEATS.md).

![The cheat overlay on a real Pocket: a header reading "10 CHEATS 11 CODES" and "CARTRIDGE", then the name of every enabled cheat drawn over the running game](docs/images/overlay-cartridge.png)

The core menu has no room to name cheats, so the names are drawn over the game
instead, with the state of each switch. The header counts what the file held
and says whether the game came from a cartridge or from a file on the card.
(The picture predates the slots.)

> **Cheats can corrupt save files.** A GameShark code is a write into the memory
> of a running game, made once a frame, and a game builds its save data out of
> that same memory. A code aimed at an address that means something else in your
> copy overwrites whatever is there, and the damage is written into your save at
> the next save point. That is worst on a cartridge, where the save lives in the
> cartridge and nothing on the SD card is a backup of it. Back up anything you
> care about first, and read [docs/CHEATS.md](docs/CHEATS.md#cartridges) before
> putting codes on a cartridge.

## Versions

Versions use `0.9999.YYYYMMDD`, where the date is UTC. Release tags add `v`,

## Installation

Prebuilt cores are on the [Releases](../../releases) page. Download
`kroy.GBC_<version>.zip` and `kroy.GB_<version>.zip`, not the "Source code"
archives: the bitstream is not committed, so a core
installed from a source archive is listed by the Pocket and cannot start.

These install as `Cores/kroy.GBC` and `Cores/kroy.GB`. They do not replace an
upstream `budude2.GBC` or `budude2.GB` install, they sit beside them. APF names
a core folder after the author in its `core.json`, and these say `kroy` because
they are not budude2's builds. Delete the old folders if you do not want both
listed, and their `/Settings/budude2.*` folders with them. Saves are keyed by
platform rather than by core, so they carry over untouched; save states and
settings do not.

Copy the `Assets`, `Cores` and `Platforms` folders to the root of the SD card.
Finder on macOS *replaces* folders rather than merging them the way Windows
does, which will delete the ROMs already in `Assets`, so copy the folders inside
those three rather than dragging the three themselves.

### Boot ROMs

The cores will not start a game without one. They are copyrighted console code,
they are not in the zip, and nothing here will fetch them. Dump them from your
own hardware or supply your own copies.

| File | Goes in | Size |
|---|---|---|
| `gbc_bios.bin` | `/Assets/gbc/common/` | 2304 bytes |
| `gb_bios.bin` | `/Assets/gb/common/` | 256 bytes |
| `sgb_boot.bin` | `/Assets/gb/common/` | 256 bytes |

## Usage

ROMs go in `/Assets/gbc/common/` and `/Assets/gb/common/`.

Cheat files go beside the ROM, named after it, in the libretro `.cht` format.
For a cartridge there is no ROM to sit beside, so the file goes in
`/Assets/<platform>/common/Cartridges/` and you load it once with **Load
Cheats** in the core menu; the slot remembers it afterwards.

**Cheats enabled** in the core menu turns the whole lot on and off. Under it,
the first two cheats in the file are two slots: **Cheat slot 1** and **Cheat
slot 2** turn each on and off whatever the file says, and every later cheat
follows its own `enable` key. **Show cheats** draws the switches and the
names over the picture, with a header giving the counts and saying whether
the game came from a cartridge or a file. That overlay is the diagnostic
surface: it is the one place a core can put text, and it says in words what
an empty screen would leave you guessing at.

All the switches are off at every launch and none is remembered. They have an
address each rather than bits of one word, because sharing a word meant each
checkbox had to preserve the others' bits through its mask, and on hardware
that did not hold: toggling one switch cleared the other and the second
checkbox did nothing.

The diagnostics are on screen rather than in the menu. `0xF3000004` and
`0xF3000008` carry the byte, cheat and code counters for anyone reading them
over the bridge. [docs/CHEATS.md](docs/CHEATS.md) has the detail.

Game Genie codes carry a compare byte and are checked before they are applied,
so on the wrong revision of a game they simply do nothing. GameShark codes carry
no such check and are written regardless. On a cartridge, whose revision you
cannot read from the outside, that difference is the whole argument for
preferring Game Genie.

## The desktop app

[pocket-tools](https://github.com/kroy-the-rabbit/pocket-tools) is the desktop
side of this set. It reads your Pocket SD card, lists the games on it, matches
each against the libretro cheat database and writes the cheat file beside the
ROM. It handles the cartridge case too, and it will install and update these
cores for you.

You do not need it. A cheat file written by hand works exactly the same. It
exists because picking cheats out of a few thousand database files by hand is
tedious.

## Building from source

Quartus runs in a container and nothing is installed on the host:

```sh
make all      # both cores
make gbc      # just the Game Boy Color core
make gb       # just the Game Boy core
make test     # the simulation suite
```

Builds here differ from upstream's in one way that is not the cheats: the fitter
runs STANDARD FIT with hold-time optimisation rather than FAST FIT, so timing
closure is repeatable rather than swinging on the seed.
`tools/podman/build-core.sh` says why.

The build fails if the design misses timing. Quartus exits 0 on negative slack,
so the harness checks worst-case slack itself and stops, because a bitstream
with negative slack may work on one bench and fail on somebody's handheld.

## Where to report a problem

Cheat engine bugs belong here. Bugs in the cores themselves are most likely the
Pocket port's rather than MiSTer's, so they belong
[upstream](https://github.com/budude2/openfpga-GBC/issues) and will be forwarded
from here as necessary.
